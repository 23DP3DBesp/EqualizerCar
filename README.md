# EqualizerCar

EqualizerCar - SwiftUI-аудиоплеер для прослушивания музыки в автомобиле. Приложение объединяет локальную медиатеку, продвинутый эквалайзер, bass-oriented DSP-режимы, эффекты, плейлисты, пресеты и резервное копирование.

Проект построен вокруг `AVAudioEngine` и модульной DSP-цепочки. Интерфейс выполнен в светлой минималистичной стилистике: белый фон, чёрный текст и умеренные красные акценты и рассчитан на быстрый доступ к воспроизведению, библиотеке и настройкам звучания.

## Возможности

- Локальная библиотека аудиофайлов с массовым импортом
- Мини-плеер, полноэкранный экран Now Playing, очередь, shuffle, repeat, избранное и недавно прослушанные треки
- Плейлисты и быстрые разделы библиотеки
- Поиск и сортировка по названию, дате добавления, длительности, последнему воспроизведению и избранному
- Многополосный эквалайзер с настраиваемым количеством полос и типами фильтров
- Bass Lab с режимами настройки под автомобильное звучание
- DSP-эффекты: bass boost, treble boost, loudness, compressor, limiter, multiband compressor, soft clipper, reverb, crossover, phase inversion, stereo widening, spatial audio, surround и 8D audio
- Управление встроенными и пользовательскими пресетами
- Опциональные per-track preset snapshots
- Backup/restore для треков, плейлистов, пресетов и текущих настроек эффектов
- Поддержка фонового аудио
- Оптимизация для больших библиотек: waveform не сохраняется в метаданных каждого трека, а массовый импорт обновляет библиотеку пакетно

## Навигация и воспроизведение

Основные вкладки: **Player, Library, Effects, More**. На широком экране используется sidebar с Home, Library, Favorites, Recently Played, Playlists, Effects и More. Bass Lab, Presets, Car Tools, Drive Mode и Settings доступны в More.

`playbackSource` и `playbackIDs` задают текущий список и его порядок. При открытии раздела, выборе плейлиста или запуске домашней карточки список обновляется. Next, Previous, Shuffle и автоматическое продолжение используют только этот список. Пустой или удалённый список не подменяется всей библиотекой. Изменения состава Favorites и плейлистов синхронизируются с очередью без перестановки треков при обновлении метаданных.

`queueIDs` — ручные запросы «следующим» внутри текущего списка; смена списка очищает эти запросы. Repeat One применяется к окончанию трека, а ручной Next переходит к следующему. Shuffle хранит историю для Previous и при выключенном Repeat останавливается после доступных треков.

Исполнитель и обложка читаются из метаданных аудиофайлов. Если их нет, интерфейс показывает Unknown artist и нейтральную обложку. Старые JSON-индексы и SwiftData-записи поддерживаются.

Проверка очереди без запуска аудиоустройства: `python3 Tests/check_playback_queue.py`. Проверка исполняет методы очереди из исходного LibraryManager с тестовым аудиоменеджером; она не заменяет проверку звука на устройстве.

## Архитектура

Приложение использует несколько stateful-менеджеров, которые передаются в SwiftUI-экраны:

- `AudioEngineManager` управляет воспроизведением, `AVAudioEngine`, параметрами эффектов, метрами, remote commands и now-playing metadata.
- `LibraryManager` управляет треками, плейлистами, очередью, избранным, сортировкой, поисковыми кешами и сохранением метаданных.
- `PresetManager` управляет встроенными пресетами, пользовательскими пресетами, quick presets и import/export пресетов.

Аудиоцепочка собирается через `AudioGraphBuilder`, а отдельные эффекты вынесены в `DSP/Plugins`. Такой подход упрощает добавление новых эффектов и ограничивает изменения внутри конкретного плагина, если не требуется менять весь audio graph.

## Производительность

- Частые значения времени и аудиометров используют отдельный `AudioTelemetry` с Observation: изменение спектра не рассылает `objectWillChange` всему приложению.
- JSON библиотеки загружается вне главного потока. Сохранения объединяются в последовательной фоновой очереди и записываются атомарно; при уходе в фон последняя версия сохраняется перед приостановкой приложения.
- Метаданные извлекаются последовательно в фоновом задании и применяются пакетами до 24 треков. Проверенные файлы, в том числе без обложки или исполнителя, не сканируются при каждом запуске.
- Декодированные обложки разделяют ограниченный кэш на 24 МБ. Декодирование больше не выполняется в `View.body`.
- Сверка очереди и история Shuffle используют множества идентификаторов вместо вложенных линейных поисков.

Проверки: `python3 Tests/check_audio_observation.py`, `python3 Tests/check_playback_queue.py` и `python3 Tests/check_library_storage.py`. Это проверки кода, очереди и сохранений; измерение FPS и задержек на реальном устройстве выполняется отдельно через Instruments.

## Быстрый старт

### Требования

- Xcode с поддержкой SwiftUI, SwiftData и AVFoundation
- Симулятор или устройство Apple, подходящее под target проекта

### Запуск

1. Откройте проект:

   ```bash
   open EqualizerCar.xcodeproj
   ```

2. Выберите scheme `EqualizerCar`.
3. Выберите симулятор или подключенное устройство.
4. Запустите build из Xcode.

## Использование

1. Откройте вкладку Library и импортируйте аудиофайлы.
2. Запустите трек из библиотеки, плейлиста, очереди, избранного или Home shortcuts.
3. Настройте звучание во вкладках Effects и Bass Lab.
4. Сохраните пользовательский пресет во вкладке Presets.
5. Используйте Settings для экспорта или восстановления backup.

## Данные и хранение

Импортированные аудиофайлы копируются в папку библиотеки внутри Documents приложения. Метаданные треков хранятся отдельно через SwiftData и JSON-совместимые модели.

Backup может включать:

- Треки и метаданные
- Плейлисты
- Аудиофайлы
- Пользовательские пресеты
- Текущие настройки эффектов
- Дату экспорта

## Производительность

Проект рассчитан на большие локальные библиотеки. Для снижения лагов при 1000+ треках:

- waveform samples не сохраняются в `Track`, JSON index и SwiftData;
- массовый импорт добавляет новые треки одним пакетным обновлением;
- кеши поиска, избранного и недавно прослушанных треков пересобираются после пакетного обновления, а не после каждого файла;
- UI waveform использует легкий placeholder, если нет готовых samples.

## Рекомендации по разработке

- Держите DSP-логику внутри `DSP/Plugins`, если изменение не требует перестройки всего audio graph.
- Для SwiftUI-состояния используйте `@State`, `@StateObject`, `@ObservedObject` и async/await-подходы.
- Для больших операций с библиотекой предпочитайте пакетные обновления.
- Не сохраняйте тяжелые derived data, например waveform samples, в основной модели трека.
- Перед завершением изменений в audio graph, persistence или импортерах выполняйте сборку проекта в Xcode.
